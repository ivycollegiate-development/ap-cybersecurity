# U2 L21: Unit 2 Synthesis — Build a Physical Security Program (Oct 28, Wed — PAPER DAY)

**⚡ HW Quiz (5 min):** 3 MCQ on the mock sprint rationales, weighted to the objectives that were most-missed on Tuesday.

**Learning Objectives:**
- 2.1.A–2.1.D the four phases of a cyberattack, applied to a physical entry point
- 2.1.E Assess risk for a named threat to the new office
- 2.1.F Select and justify a treatment option for each top risk
- 2.2.A–2.2.C physical vulnerabilities and attacks
- 2.3.A locks and access controls, 2.3.B surveillance / CCTV, 2.3.C environmental and monitoring controls
- 2.4.A access/badge log monitoring, 2.4.B video and log correlation, 2.4.C alerting thresholds and response

**Materials:** Slides, Taichung scenario brief, layered program design sheet (six zones, one control column and one objective-code column per control), presentation rubric, Unit 2 study guide issued at the end of class

**No computers today.** Paper day — the program is designed on the handout. Groups of four.

---

## Activities

1. **Scenario brief (8 min):** **A Taiwanese semiconductor firm is moving into a new office in Taichung.** Fourteen months ago they were two engineers in a rented floor of a shared building. Now: 180 staff, a design floor, a clean-room support area, a network closet, a server room, and a reception desk. The building is shared with three other tenants and has a shared lobby. The clean-room supplier audits them annually. Two typhoon seasons have already hit the new site.

   Ask: what is the threat model now, compared to what it was fourteen months ago? The answer students should reach: the threat did not get better because the company got more careful — it got worse because the company got worth attacking, and because the shared lobby is an access surface the firm does not control.

2. **Group design — layered physical security program (25 min):** Each group designs a layered program across six zones. Perimeter, entry control, interior zones, monitoring, detection, response. Every control must be justified by **naming the learning objective it satisfies** — the code goes in the second column. A control with no objective code does not go on the sheet.

   Push groups past the obvious. If a group's entry control is a badge reader, ask which physical attack the badge reader does nothing about (2.2.A tailgating). If their monitoring is CCTV, ask what a camera does not generate (2.4.A — cameras are not logs; the badge log is where the correlation of 2.4.B comes from). If their response is "alert security," ask for the named owner and the action.

   Local texture worth using if you have it: typhoon and flood resilience for the server room and the ground-floor network closet (2.3.C), a shared lobby where a guard controls one entrance to four tenants, and the fact that an ISP or a landlord-controlled utility entry is an access path nobody on the team owns.

3. **Group presentations (8 min):** Two minutes per group. Controls and objective codes only — no narrative. The class listens for objective codes, and I write them on the board.

4. **Class gap hunt (4 min):** Read the objective codes off the board and compare against the full objective list. **Which learning objective did no group cover?** That gap is the honest result of today, and it is the first item on the re-teach board for Nov 9.

**Homework (due Thu 20:30 — break audit quiz):** Your Unit 2 study guide is issued at the end of class — this is the copy you use for the Nov 9–12 review block and the Nov 13 test. Complete section 1 tonight: every objective code, and for each one the control you would build first at the Taichung site. One line each. The break audit quiz on Thursday uses Unit 2 objectives alongside the audit content.

**Differentiation / ELL support:** The design sheet is pre-formatted with the six zones and both columns already labelled, so the work is deciding and justifying, not formatting. Objective codes are printed in a reference strip along the edge of the sheet. Groups may present from the sheet itself rather than building slides. Gap-hunt discussion works well as a whole-class call-out of codes, so a student who struggles to speak can name a code and have the class respond.
