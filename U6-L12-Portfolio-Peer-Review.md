# U6-L12: Portfolio Peer Review and Revision

**AP Cybersecurity — ICA 2026-27**  
**Date**: May 27, 2027 (Thu) | **Period**: 133 | **Duration**: 50 min  
**Type**: Peer Review | **Format**: Structured Review + Revision Sprint

---

## Learning Objectives

By the end of this lesson, students will be able to:
1. **Evaluate** a peer's portfolio against Portfolio-Rubric.md with specific, actionable feedback
2. **Receive** feedback without defensiveness; distinguish preference from requirement
3. **Prioritize** and execute final revisions before presentation day
4. **Calibrate** self-assessment against peer and teacher perspectives

---

## Prerequisites

- Portfolio Build Day 2 complete (PORTFOLIO.md all sections, repo polished)
- Self-score rubric completed (U6-L11)
- Peer review partner assigned (teacher pairs complementary strengths)

---

## Materials

- Portfolio-Rubric.md (review criteria)
- Peer review form (2 pages: rubric scores + narrative feedback)
- Timer (structured review rounds)
- Revision checklist template

---

## Lesson Flow

| Time | Activity | Details |
|------|----------|---------|
| 0-5 | **Review Norms** | "Kind, specific, actionable. 'Good job' ≠ feedback. 'Section 3.2 missing LO codes for features 2-3' = feedback. You're the reviewer you'd want." |
| 5-25 | **Structured Peer Review** (20 min) | **Round 1 (10 min)**: Reviewer reads portfolio (PORTFOLIO.md + repo), completes rubric scores (1-5 per dimension), writes 3 strengths + 3 improvements<br>**Round 2 (10 min)**: Switch roles. Same process. |
| 25-35 | **Feedback Exchange** (10 min) | Pairs discuss:<br>1. Reviewer shares scores + top 1 strength + top 1 improvement<br>2. Reviewee asks clarifying questions (no defending)<br>3. Both note: "I will fix X" / "I disagree with Y because Z" |
| 35-43 | **Revision Sprint** (8 min) | Students address **top 2 peer-identified issues**:<br>- Quick fixes: typos, broken links, missing badges, LO code additions<br>- Deeper fixes: threat model traceability, reflection specificity, demo link<br>Teacher circulates: "What are you fixing? Show me." |
| 43-48 | **Final Commit** (5 min) | `git add . && git commit -m "Peer review revisions: [brief summary]" && git push`<br>Update self-score rubric with peer-informed adjustments. |
| 48-50 | **Presentation Logistics** (2 min) | Teacher confirms: May 28 order, room setup, timer, recording, audience (admin, parents?), Q&A time. "Bring: slides on USB + GitHub backup. Wear: professional." |

---

## Teacher Notes

- **Pairing strategy**: Strong writer + strong coder; Light Option + Standard; different capstone labs
- **Review form**: Rubric scores (1-5 each dimension) + narrative (Strengths / Improvements / Questions)
- **Time**: Keep rounds tight — 10 min read+score is fast; skim for rubric criteria
- **Disagreements welcome** — "I scored you 3 on Documentation because..." → dialogue

---

## Differentiation

| Need | Adjustment |
|------|------------|
| Anxiety | Allow written-only exchange; teacher mediates verbal |
| ELL | Provide feedback sentence starters; allow Chinese notes |
| Light Option | Reviewer aware of adjusted expectations (max 60/100) |
